🔬 Detection Methods Implemented

1. Multi-Strategy Hybrid Detection

Combines 4 complementary strategies to maximize anomaly detection:

Strategy 1: Simple Threshold Detection
Values > baseline + 0.5σ flagged as anomalies

Strategy 2: Percentage Change Detection
Deviations >20% from baseline detected

Strategy 3: Fault Window Correlation
Time windows (±2 units) around known faults marked

Strategy 4: Drift Detection
Values deviating >15% from first-half baseline detected

2. Baseline-Aware Anomaly Detection

Establishes normal behavior patterns from pre-fault metrics (first 10 time points). Compares all subsequent values against this baseline to identify deviations.

3. Service-Specific Classification

Classifies anomalies into 3 incident categories based on service type:

Service A → Resource Exhaustion
Service B → Performance Degradation
Service C → Service Unavailability

4. Confidence Scoring

Calculates confidence scores based on deviation percentage from baseline. Each service has thresholds to normalize deviation into 0-1 confidence scale.

5. Time-Based Correlation Detection

Identifies correlated faults across services within temporal windows (within 3 time units). Enables root cause analysis by detecting related incidents.

✅ Security Hardening Recommendations - Implement these for production deployment

🔒 Security Best Practices (21 Items)

Authentication & Authorization (Items 1-6)

1. Hide API Keys: Use environment variables, not hardcoded

# ❌ Bad
API_KEY = "sk_live_abc123"

# ✅ Good
import os
API_KEY = os.getenv('AIOPS_API_KEY')

2. Purge Git Secrets: Remove sensitive data from git history

git-crypt lock # Encrypt sensitive files
.env # Add to .gitignore
credentials.json # Add to .gitignore

3-6. Auth & Sessions:

  • Enforce server-side authentication (don't trust client)
  • Secure session cookies with HttpOnly, Secure, SameSite flags
  • Hash passwords with bcrypt/argon2
  • Rate limit login attempts

Data Protection (Items 7-10)

7. Row-Level Security: Enforce data access per user role

8. Encrypt Sensitive Data: Use AES-256 for data at rest

9. Lock Record Access: Prevent unauthorized field modification

10. Block Field Tampering: Validate all input server-side

API Security (Items 11-18)

11. Parameterize Queries: Prevent SQL injection

# ❌ Bad (SQL injection vulnerable)
query = f"SELECT * FROM users WHERE id = {user_id}"

# ✅ Good (parameterized)
query = "SELECT * FROM users WHERE id = ?"
cursor.execute(query, (user_id,))

12. Validate All Input: Whitelist expected values

13. Escape User Content: Prevent XSS attacks

14. Restrict File Uploads: Validate file type and size

15. Trim API Responses: Return only needed fields

16. Add Security Headers: CSP, X-Frame-Options, HSTS

17. Bot Protection: Rate limiting, CAPTCHA

18. Force HTTPS: Redirect HTTP to HTTPS

Compliance & Monitoring (Items 19-21)

19. Scan Dependencies: Use safety/bandit for vulnerabilities

pip install safety
safety check # Scan for known vulnerabilities

pip install bandit
bandit -r src/ # Security issue detection

20. API Documentation (Swagger): See API Docs tab →

21. Logging & Audit Trail: Track all API calls with timestamps
